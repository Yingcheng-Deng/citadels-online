# 架构与维护

## 请求与状态

浏览器每 1.8 秒拉取一次房间的个人视图，操作后立即更新。服务端使用完整规则状态执行操作，D1 数据库持久化每个房间的 JSON 快照。没有依赖单台服务器内存的房间，不会因 Worker 重启丢局。

每项写入附带 `revision`。数据库执行 `UPDATE … WHERE revision = ?`：只有一项并发写入能成功，其他请求收到 409 后重新读取。避免准备、加入、出牌之间覆盖彼此。

## 私密信息

每位玩家得到一个 256 位随机席位凭证。数据库仅保存其 SHA-256 摘要。浏览器将凭证保存在当前标签页的 sessionStorage；恢复密钥支持换设备。密钥不出现在邀请链接中。

`lib/game.ts` 的 `view()` 是公开状态唯一出口：其他人的手牌、未公开角色、完整牌库、随机弃角和凭证摘要不会发送到客户端。当前选角者只收到 `draftSlots` 牌背位置，不收到角色身份；选角与弃角提交 `slot`，服务端解析对应角色，并在后续选择前重新洗牌。旧客户端提交角色编号会被拒绝并提示刷新。位置在同一 revision 内稳定，刷新不改变牌序，过期操作仍由 CAS 拒绝。手牌视图按类别、造价和建筑名称标识排序，不改变存档中的手牌顺序或卡牌 ID。服务器检查席位、阶段、回合、费用、使用次数与目标合法性。React 文本输出避免昵称被当作 HTML 执行。

房间码是邀请信息，不是席位凭证；知道码的人仅能在开局前以新席位加入。任何人持有恢复密钥即可使用该席位。没有注册或找回系统，密钥遗失后目前不能恢复进行中的席位。

## 运行与限制

托管使用 Sites / Cloudflare Worker + D1；开发使用 Vinext + Miniflare 模拟相同存储。GitHub 保存源码与 CI，GitHub Pages 不提供这套游戏需要的服务端数据库。

当前面向小规模朋友房间：没有机器人、聊天、围观、掉线托管、踢人、账号系统、房间列表、过期清理、IP 限流或大规模压测。掉线后等待原玩家带密钥回来。不要把当前版本当作已完成滥用防护的商业大厅。

D1 中保留昵称、手牌/城市、回合及最近150条事件；不采集邮箱或真实姓名。Git 中不包含房间数据、运行日志、凭证或原始照片。原始照片仍在上层 `citadels` 目录。

## 扩展路径

2026-11 更新：`newDeck()` 每局从 30 种独特建筑中不重复抽选 14 种，保持低、中、高造价覆盖，加 54 普通建筑；`uniqueKeys` 随存档持久化并作为公共组合名单返回，不暴露牌序。旧快照缺少该字段时由存量牌恢复名单。

博物馆把暗藏牌保存在建筑的 `stored` 数组中，个人视图只暴露 `storedCount`，拆除时递归内容回到牌库底。剧院用 `theaterPending` 在选角完毕、叫号之前暂停，只有持有者能交换或跳过；交换不提前公开角色。纪念碑用 `citySize()` 计算完城进度，普通建筑计数与计分仍按真实卡片数。幽灵区终局自动选择使五色/议会/象牙塔/许愿井合计得分最高的颜色。

`components/tutorial.tsx` 是独立的本地练习，不调用房间 API。首次访问提示与完成状态存入 localStorage；随时可从导航重新打开。`GameDialog` 使用原生模态对话框处理焦点与 Escape。原版卡面以逐卡 WebP 静态文件本地托管，生成来源记录在 `docs/ARTWORK.md`。

新增角色应先补齐 `roles` 元数据、角色选择配置、规则处理及边界测试，再添加 UI。额外建筑同理。不要直接在前端改变金币或城市；新增操作必须经过服务端 `apply()` 与 CAS 写入。

修改数据库结构后运行 `npm run db:generate`，检查并提交新迁移。不要修改已发布的旧迁移。改动规则前先核对 2021 实体版本及卡面。
